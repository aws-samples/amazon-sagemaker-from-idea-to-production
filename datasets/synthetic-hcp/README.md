# Synthetic HCP prescribing dataset

All notebooks in this workshop use a **synthetic** dataset of healthcare practitioners (HCPs),
generated by [`generate_hcp_data.py`](generate_hcp_data.py). No real HCPs, brands, patients or
prescriptions are included. The data is shaped like a typical pharma commercial analytics
problem, so you can practice MLOps on a realistic use case:

> For each HCP, every week: will this HCP write at least one prescription (Rx) for our brand
> in the **next 4 weeks**?

The generator is part of this repository and released under the same MIT-0 license.
Notebook `00-start-here.ipynb` runs it, which takes a few seconds. The output is the same on
every run (fixed random seed), so everyone in the workshop works with identical data.

```bash
python datasets/synthetic-hcp/generate_hcp_data.py --output-dir data/synthetic-hcp
```

## Files produced

| File | Weeks | Rows | Used for |
|---|---|---|---|
| `hcp_weekly_snapshots.csv` | 1-20 (2025-01-06 to 2025-05-19) | 100,000 | Training, validation and test in notebooks 01-05 |
| `hcp_weekly_snapshots_after_launch.csv` | 21-26 (2025-05-26 to 2025-06-30) | 30,000 | "New production data" for drift monitoring in notebook 06 |

Each row is one HCP in one week (5,000 HCPs x 26 weeks). The history columns summarize the
weeks *before* the snapshot week. The target looks at the 4 weeks *after* it.

## Columns

| Column | Type | Meaning |
|---|---|---|
| `hcp_id` | ID | Synthetic HCP identifier |
| `week_start_date`, `week_index` | Time | Snapshot week (1-26) |
| `specialty` | Profile | Rheumatology, Dermatology, Gastroenterology, Allergy/Immunology, Primary Care, Internal Medicine, Nurse Practitioner, Other |
| `region` | Profile | Northeast, Southeast, Midwest, Southwest, West |
| `practice_type` | Profile | Academic, Hospital, Group practice, Solo practice |
| `segment` | Profile | A-D, by market volume (A = top 25%) |
| `formulary_access` | Profile | Preferred, Covered or Restricted access for the brand |
| `graduation_year` | Profile | Year of graduation (about 3% missing) |
| `patient_visits_weekly` | Profile | Average patient visits per week (about 2% missing) |
| `brand_rx_last_4w`, `_13w`, `_26w` | Rx history | Our brand's prescriptions in the last 4, 13 and 26 weeks |
| `competitor_rx_last_13w` | Rx history | Competitor prescriptions in the last 13 weeks |
| `market_rx_last_13w` | Rx history | All prescriptions in the therapy area in the last 13 weeks |
| `rep_calls_last_4w`, `_13w` | Outreach | Sales rep calls |
| `samples_last_4w` | Outreach | Sample units left |
| `emails_last_4w` | Outreach | Marketing emails sent |
| `speaker_events_last_13w` | Outreach | Speaker programs attended |
| `brand_rx_next_4w` | **Target source** | Our brand's prescriptions in the **next** 4 weeks. Not known at scoring time |

The workshop turns `brand_rx_next_4w` into a yes/no label (`prescribed_next_4w` = 1 when it is
greater than 0) and then drops it from the features. Predicting the count itself is a natural
extension (a regression model, scored with RMSE or MAE instead of AUC).

## What is built into the data

- **Profile effects:** specialty, segment, practice type, formulary access and years in
  practice change how likely an HCP is to prescribe the brand.
- **Outreach works, with limits:** rep calls, samples, emails and speaker programs raise
  brand share. The effect carries over for a few weeks and has diminishing returns.
  Reps call more often on high-volume HCPs, as they do in practice.
- **Lots of zeros:** about half of all HCP-weeks have no brand Rx in the next 4 weeks.
- **Noise:** week-to-week ups and downs that no model can predict.
- **Competitor launch in week 21:** a competitor product takes share, most strongly in
  Rheumatology, Dermatology and Allergy/Immunology, and unevenly across HCPs. It also grows
  the market there, and the brand team responds with more emails and rep calls.
  The share of HCPs with a brand Rx in the next 4 weeks falls from about 51% to 39%.
  A model trained before the launch keeps predicting the old rate, which is exactly what
  the monitoring in notebook 06 is designed to catch.

As a reference point, a model that only looks at `brand_rx_last_13w` reaches an AUC of about
0.83 on the test weeks. A model using all features should clearly beat it.
